# 视觉识别流程图与异常规则

## 1. 主流程

```mermaid
flowchart TD
    A[MuMu 截图或窗口帧] --> B{分辨率为 1920×1092?}
    B -- 否 --> X[暂停识别并提示重新选择配置]
    B -- 是 --> C[按配置裁剪五个商店卡槽]
    C --> D[统一模板尺寸]
    D --> E[灰度化与 CLAHE 亮度归一化]
    E --> F[归一化互相关模板匹配]
    F --> G[输出 Top-1 ID 与置信度]
    G --> H[保存最近 5 帧结果]
    H --> I{至少 3 帧 ID 一致?}
    I -- 否 --> J[继续采样，不更新稳定结果]
    I -- 是 --> K{置信度 ≥ 0.85?}
    K -- 否 --> L[黄色低置信度，必须人工选择]
    K -- 是 --> M[显示建议结果，等待用户核对]
    L --> N{用户确认且确认已购入?}
    M --> N
    N -- 否 --> O[不写入已有资源]
    N -- 是 --> P[转换为稳定英雄 ID]
    P --> Q[合并到手动输入并调用推荐 API]
```

## 2. 固定参数

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| 配置 | `mumu-6.8.7-shop-1920x1092` | 只用于已验证环境 |
| 采样频率 | 1 FPS | 第二周设计值，后续可调至 2 FPS |
| 匹配阈值 | 0.85 | 未达到时强制人工确认 |
| 稳定窗口 | 最近 5 帧 | 防止动画瞬时误判 |
| 最少一致帧 | 3 帧 | 未达到时不更新结果 |
| 首版算法 | 灰度 + CLAHE + 模板匹配 | 不使用 OCR，不读取游戏内存 |

## 3. 异常与降级

- 分辨率、DPI 或商店布局变化：暂停并重新标定，禁止静默沿用坐标。
- 窗口最小化、截图为空或卡槽被遮挡：标记识别失败，不产生英雄 ID。
- 多个模板得分接近：显示候选列表，由用户选择。
- 商店英雄只代表可购买候选，不代表已经拥有；用户必须确认“已购入”。
- 识别模块不可用时切换到手动输入，推荐功能仍可演示。

## 4. 模块边界

视觉模块只输出候选 ID、置信度、卡槽和确认状态。前端负责人工确认，后端只接收已确认的稳定 ID；视觉模块不直接操作游戏，也不直接调用推荐评分逻辑。
