# 前端目录、路由与状态设计

## 1. 技术选择

- Vue 3 + Vite + TypeScript。
- Vue Router 管理页面导航。
- Pinia 管理用户已选资源、识别候选和推荐结果。
- `fetch` 封装在 `services/`，组件不直接拼接后端地址。

## 2. 正式工程目录

```text
frontend/
├─ src/
│  ├─ api/                 # HTTP 客户端、请求与响应类型
│  ├─ assets/              # 项目自有静态资源
│  ├─ components/
│  │  ├─ common/           # 加载、空状态、错误提示
│  │  ├─ resources/        # 英雄和装备选择器
│  │  ├─ recommendations/  # 推荐卡片和分项评分
│  │  └─ vision/           # 截图预览、候选项和确认控件
│  ├─ router/              # 路由表与导航守卫
│  ├─ stores/              # Pinia 状态
│  ├─ views/               # 页面级组件
│  ├─ types/               # API V1 与视觉候选类型
│  ├─ App.vue
│  └─ main.ts
├─ mocks/                  # 与 API V1 同字段的固定模拟数据
├─ prototypes/week1/       # 第一周无依赖交互草图
└─ tests/                  # 组件、状态和接口适配测试
```

第二周只冻结结构，不提前初始化第四周才需要的完整 Vue 工程。

## 3. 路由设计

| 路径 | 页面 | 主要职责 |
| --- | --- | --- |
| `/` | `HomeView` | 项目说明和功能入口 |
| `/data` | `DataBrowserView` | 浏览英雄、装备、羁绊和阵容 |
| `/resources` | `ResourceInputView` | 手动选择已有英雄、装备和 Top K |
| `/vision` | `VisionConfirmView` | 展示截图、候选、置信度并人工确认 |
| `/recommendations` | `RecommendationListView` | 展示 Top K 与分项评分 |
| `/lineups/:lineupId` | `LineupDetailView` | 展示站位、核心装备、统计和来源 |

推荐页刷新后若内存中没有请求输入，应返回 `/resources` 并提示重新生成，不伪造结果。

## 4. Pinia 状态划分

### `useResourceStore`

- `championIds: string[]`：英雄去重。
- `itemIds: string[]`：允许重复。
- `topK: number`：限制为 1–10。
- `add/remove/clear`：所有页面共用，接口失败时不清空。

### `useVisionStore`

- `framePreviewUrl`：当前预览。
- `candidates`：`kind/id/confidence/region/confirmed/ownership`。
- `captureStatus`：`idle/capturing/paused/failed`。
- 低于阈值的候选不能自动确认；商店候选还必须确认已经购入。

### `useRecommendationStore`

- `status`：`idle/loading/success/empty/error`。
- `results`：API V1 推荐响应。
- `lastRequest`：用于重试，失败时保留。
- `errorMessage`：展示可理解的失败原因。

## 5. 页面状态规则

| 状态 | 界面行为 | 输入处理 |
| --- | --- | --- |
| 加载 | 禁用重复提交，显示“正在计算推荐…” | 保留 |
| 空输入 | 允许请求，但提示主要依据公开强度 | 保留 |
| 空结果 | 显示原因和返回修改入口 | 保留 |
| API 失败 | 显示重试与错误摘要 | 保留，使用 `lastRequest` 重试 |
| 识别失败 | 提供手动输入入口 | 不阻断其他页面 |
| 低置信度 | 黄色问号和候选选择器 | 人工确认前不得合并 |

## 6. API 映射

- `useResourceStore` 通过适配器生成 `champion_ids`、`item_ids`、`top_k`。
- `RecommendationListView` 使用 `lineup_id`、`lineup_name`、`score`、`breakdown`。
- 阵容卡使用 `missing_core_champions`、`craftable_recommended_items` 和 `explanation`。
- 模拟请求与响应位于 `frontend/mocks/`，字段与 `docs/API接口文档V1.md` 一致。
