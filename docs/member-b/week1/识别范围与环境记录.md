# 识别范围与环境记录

记录日期：2026-10-19。赛季与版本按项目快照记录为 S18 / 18.4。

## 已确认的场景

- 运行环境：Windows 上的安卓模拟器；具体模拟器待用户提供。
- 游戏界面：对局准备阶段，商店卡牌完整可见、无弹窗遮挡的页面。
- MVP 区域：商店区五个卡位中用于辨认英雄的卡牌图像区域。
- 首个识别对象：英雄卡牌图像。商店文字不作为第一版识别对象，不使用 OCR。
- 装备图标：属于后续识别扩展，待装备区真实截图后另行标定。本周不宣称已支持。
- 帧率规划：每秒 1–2 帧，不处理游戏视频帧率。
- 输出：卡位、英雄候选稳定 ID、原始匹配分、候选相似度、帧时间、待确认状态。

商店卡牌是“可购买候选”，不是“已拥有英雄”。第一版保留手动输入已有资源；用户必须在游戏中自行购入后，明确确认该候选属于已有英雄，辅助系统才合并输入。不依据识别高分、卡位消失或连续多帧一致推断购买成功。

## 暂不识别

金币、人口、商店文字、强化符文、技能动画、战斗中的三维模型、棋盘站位、任意分辨率和任意遮挡条件。窗口捕获后续只读取屏幕画面，不读取游戏内存、不控制游戏。

## 区域标定规则

1. 先定位实际游戏内容区域，排除模拟器工具栏及黑边。
2. 在真实截图上分别测量五个卡位图像矩形，避开金币、文本和高亮边框。
3. 使用相对坐标 `[x / width, y / height, w / width, h / height]`；保存测量时的客户区宽高。
4. 坐标必须满足 x/y ≥ 0、w/h > 0、x+w/y+h ≤ 1；五个卡位不能意外重叠。
5. 客户区、DPI、分辨率或布局变化时暂停，重新选择已验证配置；不能静默沿用旧坐标。
6. 第一周配置以 `null` 表示未知参数，`enabled=false` 表示不可用于运行。

## 截图与标签要求

- 正常准备阶段截图先采 1 张用于第一周标定；第三周再扩充到正常、亮度、遮挡和缩放等至少 10 张案例。
- 原始截图路径：`data/raw/screenshots/member-b/`，不提交 Git。
- 真实标签需逐卡位人工核对，并关联 A 提供的英雄 ID。空位、未知和遮挡应明确记录，不能猜测英雄。
- 样本标签记录分辨率、DPI、采集时间、图像 SHA-256、卡位位置、真实 ID 和隐私复核状态。
- 发布截图前裁去或遮盖昵称、账号、聊天、好友列表、通知；脱敏版本单独审核。
