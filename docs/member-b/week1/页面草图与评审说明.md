# 页面草图与评审说明

本周基于已有《界面低保真原型 V1》制作可点击 HTML 草图。不是 Vue 正式页面，也不是可用视觉系统；只使用文本占位图，不抓取远程图片或素材。

## 页面与验收点

| 页面 | 交互内容 | 数据来源与限制 |
| --- | --- | --- |
| 首页 | 手动输入、识别确认、固定案例入口 | 明确展示 S18 / 18.4 及演示模式 |
| 资源输入 | 英雄搜索、去重、装备重复、删除、清空、Top K、请求预览 | 只收录部分示例英雄和基础装备；任意输入不执行评分 |
| 推荐列表 | 固定 Top 3、四项分数、缺失核心、可合成装备、理由 | A 当前后端固定输入输出快照 |
| 阵容详情 | 前/中/后三行、装备、统计、来源链接 | 静态导出阵容；详情查询接口尚未实现 |
| 识别确认 | 模拟候选、改 ID、购入确认、删除、合并、手动入口 | 置信度模拟；不捕获游戏、不执行识别 |

手动路径：首页 → 资源输入 → 固定案例推荐 → 阵容详情 → 返回列表。

视觉路径：首页 → 识别确认 → 载入模拟候选 → 核对/修改 → 确认已购入 → 合并已有资源 → 请求预览。为避免把任意识别输入与固定推荐错配，合并后不自动打开静态推荐。

直接在导航查看推荐页时仍明确标注固定案例；不根据当前用户选择假装计算结果。

## 与 API V1 对齐

- 请求只预览 `champion_ids / item_ids / top_k`。当前推荐请求模型不接受版本字段，不擅自追加。
- 四个分项为 `champion_match / item_fit / trait_coverage / meta_strength`。
- A 当前实现权重上限为 45 / 25 / 20 / 10，分项已是加权贡献值，不重复加权。
- 当前“羁绊覆盖”可能使用英雄覆盖率估计。按原样显示后端解释，不能描述成精确已激活羁绊计算。
- 总体设计规划的五项评分尚未落地；原型不额外虚构“结构完整度/成型难度”。需后续由 A 统一文档和接口。
- 稳定 ID 用于输入；返回的缺失核心与合成装备当前是名称数组，仅用于显示。
- 当前接口没有完整阵容详情，所以静态演示明确单列，后续采用查询接口或 A 提供的等价模拟数据。

## 固定案例来源

基于 `develop@99a6e39` 的 `RecommendationService`，输入三个英雄 `1507 / 2512 / 2502`，三个装备 `bf_sword / tear_of_the_goddess / recurve_bow`、Top K=3。

| 排名 | 阵容 | 综合分 |
| --- | --- | ---: |
| 1 | 射箭韦鲁斯 | 34.20 |
| 2 | 卡丽蜜儿 | 30.78 |
| 3 | 森林妖姬天使 | 25.80 |

数据在开发时显式导出到 `frontend/prototypes/week1/fixtures.js`。浏览器运行时不访问后端数据目录，不请求实时统计。

## 后续 Vue 迁移

将五页分成独立 Vue 视图，资源状态与请求预览逻辑集中管理；四项评分从实际响应渲染。按第 2 周任务设计 Router、组件和状态，再按第 4/5 周替换为查询/推荐 API。查询缺失、等待、错误与重试状态应在真实联调中实现和验证，第一周不宣称已完成。
