## 3. 推荐流程图

```mermaid
flowchart TD
    A[接收英雄 ID、装备 ID、Top K] --> B{请求字段是否合法}
    B -- 否 --> X[返回 422 字段错误]
    B -- 是 --> C[锁定 S18 18.4 数据快照]
    C --> D[过滤同版本阵容模板]
    D --> E[逐阵容计算英雄匹配度]
    E --> F[分析已有成装和可合成装备]
    F --> G{个人羁绊元数据完整吗}
    G -- 是 --> H[按实际羁绊计算覆盖]
    G -- 否 --> I[按阵容成员覆盖估算并标注]
    H --> J[加入公开统计强度]
    I --> J
    J --> K[加权得到 0-100 总分]
    K --> L[生成缺失核心与解释]
    L --> M[稳定排序并截取 Top K]
    M --> N{存在候选吗}
    N -- 是 --> O[返回结构化推荐列表]
    N -- 否 --> P[返回空列表与原因]
```

## 4. 输入到结果的数据追踪

```mermaid
sequenceDiagram
    participant User as 用户
    participant Web as Vue 前端
    participant API as FastAPI
    participant Repo as 数据仓库
    participant Ranker as 推荐服务

    User->>Web: 选择/确认英雄与装备
    Web->>API: POST /api/v1/recommendations
    API->>API: Pydantic 参数校验
    API->>Repo: 读取版本、英雄、装备、阵容
    Repo-->>API: 18.4 冻结快照
    API->>Ranker: 计算 10 套候选
    Ranker-->>API: 分项分数、缺口、解释
    API-->>Web: Top K JSON
    Web-->>User: 推荐卡片与阵容详情
```

上述链路中，每个阵容保留 `source_url`、`collected_at` 和 `sample_count`，可从推荐结果追溯到冻结数据及公开来源。
